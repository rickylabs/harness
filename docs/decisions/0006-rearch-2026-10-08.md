# ADR 0006: the 2026-10-08 re-architecture (one doctrine, one structure, no compatibility copies)

**Status:** accepted · **Date:** 2026-10-08 · **Ratified by:** Eric, through epic
[#622](https://github.com/rickylabs/harness/issues/622) and the coordinator's ratification of milestone
rearch-2026-10-08 on his delegation · **Supersedes:** [ADR 0003](0003-architecture-v1.md) where they
differ, and [ADR 0005](0005-harness-framework-identity.md) where they differ · **Issue:**
[#656](https://github.com/rickylabs/harness/issues/656)

---

## Decision

The owner asked for a new structure, doctrine and code hygiene. He asked to prune duplicate and
soon-stale code aggressively, with no backward compatibility and with regression tests only for the
parity features. The decision has seven parts:

1. **One doctrine page.** [`docs/DOCTRINE.md`](../DOCTRINE.md) holds the golden rules, the run
   invariants I1-I4, the gate states, the working rules, route authority, cost, the run lifecycle and
   the toolchain rule. The golden rules are the owner's four rules O1-O4 (idiomatic NetScript, SOLID,
   performance, the doctrine; a lower number wins), which every pull request answers, and the eleven
   doctrine rules, which are cited by number.
2. **One structure page.** [`docs/STRUCTURE.md`](../STRUCTURE.md) holds the locked target tree and the
   consumer surfaces table.
3. **Decisions live in `docs/decisions/`.** Records 0001-0005 moved there unchanged, apart from relative
   links and status notes. This record is the next one.
4. **No generated compatibility copies.** Delete, do not deprecate: no shims, aliases, pointer pages or
   delegating entrypoints.
5. **One toolchain.** pnpm workspace + Node. The method tools become a package with a bin (#658), and the
   second `deno.json` goes with them.
6. **Parity tests only for consumer surfaces.** These are the surfaces atelier-cockpit and orchid read,
   listed in `docs/STRUCTURE.md`. Other legacy tests may be deleted with the code they test.
7. **A 500-line cap per file.** Files already over it are split when touched. `.llm/runs/**` stays
   owner-controlled and is never deleted or rewritten by an agent.

## What this removes, and where its true content went

## Where this supersedes ADR 0003

ADR 0003 made `ARCHITECTURE.md` the charter, amended only by a numbered decision. The charter file is
gone. The ratified rules now live in `docs/DOCTRINE.md` and `docs/STRUCTURE.md`, amended the same way, by a
numbered decision here. ADR 0003's other consequences stand where this record does not change them:
#30's architecture stays superseded, UHP-hosted dispatch stays parked under
[ADR 0004](0004-uhp-park-evidence.md), and routing and discovery stay core work. The charter's build
order (sections 10-11) is replaced by the milestone's issue order.

## Where this supersedes ADR 0005

ADR 0005 ordered its cleanup to keep existing paths and executable names, and to keep consumer
entrypoints through compatibility copies (its ordered steps 1 and 4) until a caller census allowed
their removal. That posture is replaced by part 4 above: compatibility copies and aliases are deleted.
The consumer surfaces in `docs/STRUCTURE.md` are the only paths held stable, and they are guarded by the
parity test.

These ADR 0005 decisions stand:

- Harness is our framework on Orchid (dispatch) and Herdr (terminal control).
- NetScript is an external service behind an adapter, never a build-time dependency.
- GitHub owns the board.
- Cockpit and mobile are separate products.
- The `@rickylabs/harness-contracts` name stays stable, and contracts change only additively.
- The matrix is the default route authority, and evaluator independence is never waived.

## Cost of being wrong, and mitigation

Other repositories that send agents to the removed charter now reach a missing file. atelier-cockpit's
agent entry does this, and so does its instruction to file decisions in the former decision
directory. No shim is added. `docs/DOCTRINE.md` keeps the charter parts cockpit relies on (dispatch, the
invariants I1-I4, what is parked, decision supersession), so the cockpit follow-up only repoints
two links. If a rule was dropped that was still load-bearing, the remedy is a new numbered decision
that restores it.

## Transitional state

Completed by [#658](https://github.com/rickylabs/harness/issues/658): the method tools and the run
templates now live in `packages/method` (bin `harness-method`, templates in `packages/method/templates/`),
the Deno configuration and lockfile are deleted, and the renderer's provenance header names
`packages/method`. Status pages rendered before that keep their earlier header as history.
