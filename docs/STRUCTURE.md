# Structure

The locked target tree for this repository, the surfaces other repositories read from it, and where
new things go. The rules that shape it are in [`DOCTRINE.md`](DOCTRINE.md); the decision that locked
it is [ADR 0006](decisions/0006-rearch-2026-10-08.md). The skill
[`.claude/skills/package-layout/SKILL.md`](../.claude/skills/package-layout/SKILL.md) covers moving a
package into this shape.

## Target tree

```text
packages/
  contracts/            published @rickylabs/harness-contracts: shapes only, no logic
  routing/              matrix + model catalog (config + discovery); matrix/ is read by orchid
  subagents/            dispatch + route grammar (src/route.ts, src/dispatch.ts read by atelier-cockpit)
  coordinator/          run lifecycle
  governance/           admissions, capacity, spend (moved out of telemetry by rearch(7) #655)
  telemetry/            observation model, sinks, read models (renamed telemetry-core next night)
  providers/claude|codex|opencode/   vendor adapters (rearch(8) #659)
  hosts/orchid/         orchid dispatch + evidence adapter (rearch(9) #660)
  method/               milestone render/validate, route receipts (bin harness-method), run templates
  board/ forge/ llm-local/
  each package: mod.ts, src/{domain,application,ports,adapters}, tests/
profiles/               agent profiles; read by orchid at a pinned revision (profiles/<name>.md)
docs/                   DOCTRINE.md, STRUCTURE.md, decisions/, concepts/, how-to/, reference/, rfcs/, tutorials/
tests/parity/           consumer-surface regression tests (rearch(3) #657) - the ONLY cross-package tests
scripts/                build/check scripts referenced by package.json only
.llm/runs/              owner-controlled run records (untouched)
```

## Today versus target

The tree above is the target of milestone rearch-2026-10-08. Until each move lands, the current
location stays authoritative and the owning issue moves it:

| Today | Target | Moved by |
| --- | --- | --- |
| `packages/provider-claude`, `provider-codex`, `provider-opencode` | `packages/providers/*` | #659 |
| orchid observation files inside `packages/telemetry` | `packages/hosts/orchid` | #660 |

## Consumer surfaces

These are the only parity features (golden rule 7). Other repositories pin harness by revision and read
them directly. A pull request that moves or reshapes one edits the parity test in `tests/parity/` in the
same change and names the consumer that must follow.

| Surface | Path | Read by |
| --- | --- | --- |
| contracts package exports `.`, `./server`, `./route` | `packages/contracts/package.json` | atelier-cockpit |
| delegation matrix | `packages/routing/matrix/delegation-matrix.ts` | orchid, atelier-cockpit |
| routing policy | `packages/routing/matrix/routing-policy.ts` | orchid, atelier-cockpit |
| matrix contract | `packages/routing/matrix/contract.ts` | orchid |
| opencode preflight | `packages/routing/matrix/opencode-preflight.ts` | orchid |
| launchability | `packages/routing/matrix/launchability.ts` | orchid |
| matrix table CLI | `packages/routing/matrix/cli/delegation-matrix-table.ts` | orchid |
| routing configuration, read from `main` without a pin | `packages/routing/config/routing.v1.json` | atelier-cockpit |
| routing-proposal source (exists) | `packages/routing/matrix/matrix.test.mjs` | atelier-cockpit |
| CLI discovery | `packages/routing/src/discovery.ts` | atelier-cockpit |
| route grammar, dispatch, go grammar | `packages/subagents/src/{route,dispatch,go-grammar}.ts` | atelier-cockpit |
| governance read model | `packages/contracts/src/governance-read.ts` | atelier-cockpit |
| agent profiles | `profiles/<name>.md` | orchid |
| CLIs | `harness-board`, `harness-coordinator`, `harness-forge`, `harness-telemetry` | operators, orchid |

`packages/subagents/src/route.ts` and `dispatch.ts` stay self-contained: no new imports.
Contracts changes are additive.

## Where things go

- **A rule** goes in [`DOCTRINE.md`](DOCTRINE.md), through a decision when it changes one.
- **A decision** goes in [`decisions/`](decisions/) as the next number, `NNNN-<slug>.md`, with status,
  date, who ratified it, and what it supersedes. Earlier records are not rewritten; a later record
  supersedes them where they differ.
- **An explanation** goes in [`concepts/`](concepts/), a task in [`how-to/`](how-to/), a generated or
  exact reference in [`reference/`](reference/), a proposal in [`rfcs/`](rfcs/), a walkthrough in
  [`tutorials/`](tutorials/). A package's design rationale stays with the package: its README, plus
  a `docs/` folder beside it when one page would pass the 500-line cap (as in `packages/contracts`).
- **An agent skill** goes in `.claude/skills/<name>/SKILL.md`. `board-process` is generated by
  `pnpm run skill:install`; `doctrine`, `prune`, `parity-tests` and `package-layout` are written by hand.
- **A generated file** changes only through its generator; [`AGENTS.md`](../AGENTS.md#generated-files) lists
  each one with its command.
- **A run record** is owner-controlled under `.llm/runs/`; agents never delete or rewrite it.
