[Harness #792](https://github.com/rickylabs/harness/issues/792) is the inbox stub for audit F6 of
[atelier-cockpit #955](https://github.com/rickylabs/atelier-cockpit/issues/955), source issue

## Contract

The #960 lifecycle ledger now keeps these endpoints separate: admission, queue publication, worker
execution start and finish, Orchid launch, native task start and state, Stop request, native Stop
acceptance, seat absence and runtime absence.

- **Job execution.** NetScript's `KvExecutionState` mutation hook supplies `job_start`/`job_finish`.
  It covers only a certified single-operation execution. The hook is synchronous, detached into two
  slots, and never awaits or throws into the execution.
- **Queue publication.** The command relay sink keeps each relayed action's own queue acceptance.
  A coalesced batch is never attributed to its first action. Each drain owns its batch; only its own
  post-drain pass, after its guards are released, seals it for a single detached writer.
- **Stop acceptance.** It comes only from the bound native receipt, and never certifies either absence.
- **Edges.** Queue residence and execution service time are separate edges. Residence stays
  `binding_unavailable` until the execution names its consumed message (netscript#2588). Replays
  keep the first execution and never renew it.

Endpoints with no certified producer remain `capability_unavailable`, with their owners:
- launch queue publication: [netscript #2588](https://github.com/rickylabs/netscript/issues/2588);
- Orchid launch instant: [orchid #143](https://github.com/rickylabs/orchid/issues/143);
- vendor task start: herdr #5725;
- per-operation Stop absence certificates in the receipt reader: [harness #795](https://github.com/rickylabs/harness/issues/795).

No launch/Stop admission, answer, receipt, saga fact or drain guard gains diagnostic IO. No queue,
watcher, runtime reader, cache owner or Postgres table is added.

## Evidence and acceptance boundary

Cockpit gates on reviewed head `ab23d135` all exit 0 except one test: `check`, `lint`, `fmt:check`,
`openapi:check` (wire unchanged), `fitness`, `deploy:check` and `verify:generated`. `test` ran 2,957
passed (50 steps), 1 failed, 20 ignored. The one failure is the voice-worker parent-death `/proc`
race, which fails identically on the untouched baseline in this environment.

Twenty-three compiled behavioral controls each fail on a runtime `AssertionError`, restore
byte-identical source and pass. They cover:
- first-execution retention and same-execution pairing;
- detached-slot saturation under a stalled store;
- certified-result, batch-exclusion and claim gates;
- hook and sink failure isolation;
- the buffer bound;
- per-operation batch attribution and acceptance-after-enqueue;
- Stop-acceptance binding and acceptance-is-not-absence;
- flush after registration, capability references and residence clock domains;
- per-drain seal ownership, discard capacity, the single-flight writer, and detached Stop acceptance.

Independent evaluation used the matrix `implementation_evaluation` route: sol (`gpt-6.1-sol`, high),
a different vendor family. One session was re-steered over four rounds: three FAIL_FIX rounds, then
**PASS** with no findings on the exact tree. Repairs moved diagnostic persistence off the worker,
declared queue residence unbound until netscript#2588, stopped certifying repair-only launches, and
gave each relay drain ownership of its batch. The Cockpit sign-off commit records the verdict.

Synthetic fixtures prove typed correlation and stale/missing behavior only. No deployed stage
percentile, device latency or benchmark population is claimed. No live launch, Stop, deployment,
dispatcher setting or shared service was touched, so deployment health is unproven.
