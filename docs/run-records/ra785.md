# Native vendor startup and authentication handoff

The runtime change for [Harness #785](https://github.com/rickylabs/harness/issues/785) is in
[Orchid #142](https://github.com/rickylabs/orchid/pull/142), because Orchid owns vendor startup and supervision. Harness keeps this
record of the contract and the evidence. It hosts no Go code. Refs
[atelier-cockpit #955](https://github.com/rickylabs/atelier-cockpit/issues/955).

## Contract

Typed native facts decide startup and authentication state. Terminal text, localized strings,
quoted errors, composer hints and process identity never do. There are four states: `ready`,
`blocked`, `unauthenticated` and `unknown`. Unknown has no effect.

- **AGY startup.** The visible-screen checks are deleted: the trust, sign-in and onboarding marker
  groups, the `? for shortcuts` composer requirement, and the screen refinement of a startup
  timeout. What decides startup now:
  - Trust is prepared by construction. The per-launch settings list only the exact canonical
    checkout.
  - The CLI's typed `onboardingComplete` cache field is read before any workspace: `false` refuses
    as `startup_blocked`, and anything unproven also refuses. No seat is created.
  - One exact-occupant Herdr read follows registration.
  - The goal is confirmed only by a new native user step in the run's isolated store.
  - For AGY, Herdr's idle/ready status is display-derived. It can only fence input.
- **Authentication.** One adapter owns authentication for every transport.
  - Claude: the managed lifecycle hook now records Claude's closed `StopFailure.error` enum. Only
    `authentication_failed`, for the exact occupant and session, counts.
  - Remote Control Codex: only a newest turn with status `failed` and `codexErrorInfo:
    unauthorized` counts.
  - AGY, OpenCode and plain Codex have no typed source. They stay unknown and are never read.
  - Effect: one credential resync and one notification per native event. The event is saved
    durably before the effect runs. A suspected auth failure never tears down, re-prompts or
    redispatches a session.

## Upstream capability gaps (kept as explicit unknown)

Tracked in [Orchid #141](https://github.com/rickylabs/orchid/issues/141).

- `agy-cli-no-pre-conversation-ready-event`. AGY 1.4.12 hooks start at `SessionStart`, which fires
  on the first prompt, not at the idle composer. No typed readiness exists before the first
  conversation.
- `agy-cli-no-typed-pre-conversation-auth-state`. No typed auth state for the interactive TUI.
  `auth_required` exists only in the CLI's hidden ACP server mode.
- `agy-cli-stop-hook-error-untyped`. The `Stop` hook reports `terminationReason: ERROR` with a
  free-text `error`. Quota, auth and other failures look the same.
- Herdr's `antigravity_cli` integration (v4) reports session identity only. Its lifecycle comes
  from screen detection.

## Evidence

The evidence is in the Orchid PR body and its `docs/native-vendor-auth.md`:

- synthetic fixtures for screen invariance, stale quoted errors, stale generations, missing
  capability and effect fencing;
- `scripts/check-vendor-auth-mutations.py`, a set of compiled red/green guard controls;
- the full repository gates.

A local AGY probe used a scoped temporary settings directory and sent no prompt that consumed
quota. It established the hook timing. No AGY launch latency was measured, and no performance
improvement is claimed. Nothing was deployed and no shared service was restarted.
