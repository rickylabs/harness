# Shared native-run socket handoff

The socket lifecycle implementation for [Harness #787](https://github.com/rickylabs/harness/issues/787)
is [Orchid #139](https://github.com/rickylabs/orchid/pull/139). Harness owns the consumer deployment
guidance change in `packages/telemetry/docs/native-issue-agents.md`; it does not host the Go daemon.

## Contract

The daemon's existing `native_run_socket` config selects the pathname. The new server binds mode
0660 in a canonical dispatcher-owned 0700 or setgid 2750 parent, keeps the inherited group and
accepts only the exact kernel UID selected by `ORCHID_NATIVE_RUN_PEER_UID` (default dispatcher UID).
Missing parents report `parent-directory-missing` and invalid peer configuration reports
`peer-uid-invalid`; neither stops supervision. Safe stale 0600/0660 sockets are replaced after a
refused connect probe and an unchanged-inode check. The native JSON-lines protocol is unchanged.

The latest owner dispatch requires this group-access policy, superseding the issue's original
private-only wording. The owner-grant endpoint remains private mode 0600.

## Evidence and acceptance boundary

Orchid's new mode regression failed the previous implementation by assertion (`0600`, expected
`0660`). A compiled mode-0755 mutant also fails the exact-mode assertion, and exact restoration
passes. Tests exercise the missing-parent reason through an actual supervision tick, stale socket
replacement, group inheritance, exact peer authorization and owned-inode cleanup. The existing
isolated root CI lane now includes real configured cross-UID subscription and lookup, plus an
unconfigured-UID rejection with pathname access. Privileged local proof remains unproven in an
unprivileged run. Full upstream results and independent review are recorded in that PR.

No service, container mount or private runtime configuration was changed. Cockpit's current
`orchid-native-runs/socket.ts` rejects a socket outside its own UID and the old 0700/0600 policy.
That consumer needs an explicit shared-server identity and filesystem-policy update before this
listener can be deployed there. Existing observer-only socket and Herdr mapping settings stay on
the observer. Certified enrichment, Home Running parity and removal after completion remain live
operator acceptance checks after consumer adoption and deployment; this handoff claims none.
