# Coordinator amendment — governing over plan.md

Draft for independent review; no product mutation authorized. The standalone document/CLI path remains the proposed one-rule slice. These bounded corrections are required before implementation; preserve plan.md as history.

1. Per-source provenance: each meter read carries a safe producer-selected provenance identifier alongside original observedAt/validUntil. Admissions coverage carries a safe provenance identifier and a separate evaluated/collected timestamp where the log read provides it; do not manufacture a decision-observedAt for an empty log. Item observations retain their original stamps. Provenance identifies the reader/scope, not cryptographic trust, an account identity or a private path. Decoder verifies these required fields; fixtures prove each source survives independently.
2. Completeness means all configured requested evidence successfully read and valid, matching the producer's ok. A not-configured admissions source cannot alone force invalid when complete is true. Failed/discarded configured sources or dropped/conflicting admissions force incomplete; all-unconfigured remains unavailable/incomplete. Approvals not-observed is always explicit and is never a complete approval census. Document empty-log coverage without claiming no admissions exist outside that observation scope.
3. Temporal consistency is validated, not trusted merely because enums are valid. Reject availability/freshness that contradict evaluatedAt and validity intervals; validate real calendar dates and finite numeric ranges. Keep completion time distinct from each source observation time; reject inconsistent source-to-regime payloads and nonempty data for unread/discarded sources. Candidate must round-trip every producer outcome, including no successful meter but valid admissions, degraded log and all-unconfigured.
4. Pure decoder must terminate/refuse on bounded malformed input: nested/cyclic/accessor/sparse-array/nonfinite/wrong-prototype data, unknown keys and over-cap collections. No uncaught exception or input-value echo in diagnostics. Use schema-owned field names/indices rather than dynamic attacker keys. State normalization returns independently owned readonly data rather than an alias a caller can change after validation. No Node-only dependency enters contracts. If proxy inspection cannot be trap-free in portable JS, state that limit honestly, contain thrown traps, and do not claim arbitrary hostile JS has no side effects. JSON is the operational boundary.
5. Check-installed must execute through an existing root script that CI already runs, after the workspace build. Add to root test or its explicit post-test chain. No .github/workflows mutation: host authority lacks workflow scope. This is equivalent executable enforcement, not a skipped gate or owner blocker. Offline tarball install has no dependencies; failure remains failure, no network fallback disguised as offline. Use portable Node fixtures/owned child cleanup; timeout tests must not leak grandchildren.
6. Publication preparation includes root and server runtime/types from the actual packed installed package, package digest/version and unchanged protocol receipt. No source-only adoption. Do not claim any downstream API/client compatibility PASS. Owner alone tags/releases. The existing owner authorization permits evaluated exact-head PR merge, never automerge; release authority stays separate.
7. Plan's clock entries such as20:1xZ are approximate ordering placeholders, not exact receipts. Replace claims of exact execution times with dated attribution where logs do not establish the time. Correct relative links before publication. Imported governance types exist as direct exports too; research's wording 'solely as field' means the missing runtime read path, not a claim the type cannot be imported.

Acceptance: standalone CLI emits one decoded document with explicit source coverage, no invented board/generation, original source stamps, recorded refusal distinct from execution. Notes are informational; consumers do not parse them. Privacy canaries, malformed decoder tests, mixed sources, strict command flag refusal and installed CLI-to-package fixture are required. Decoder/root changes and telemetry additions are independently reviewed together. This does not close unverified live205/87 acceptance or recovery265.
