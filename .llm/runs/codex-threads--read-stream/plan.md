# Plan: Codex thread reads and goal subscriptions

Read and stream only. No dispatch, goal write, restart, or provider launch implementation.

Baseline: Harness 7dfefa38465ddd151a7e29360189a716ea484259. Installed codex-cli 0.154.0 generated experimental schema establishes Thread, ThreadGoal and goal updated/cleared notification fields. Official protocol: https://developers.openai.com/codex/app-server . NetScript find_guidance/search_docs and runtime source inspection found no matching read transport; provider-codex/protocol.ts is a pure start/turn port, without handshake or stdio transport.

1. Telemetry owns a narrowly allowlisted JSONL connection: initialize, initialized, thread/list and thread/goal/get only. Plain codex app-server, no proxy. Inject a byte-stream port for tests/host composition. Bound request time, frame bytes, pending requests, page/row count and notification buffer. Sanitize every failure into closed reason codes, never raw exceptions/stderr. Close only the owned child, never an existing agent or daemon. No resume/start/turn/goal mutations.
2. Export a versioned read snapshot and typed subscription from telemetry, plus codex-threads CLI read/watch entry. Snapshot projects one row per valid unique native thread, and all requested fields as available(value) or unavailable(null,reason). Native thread IDs stay private; threadId and parentThreadId are deterministic opaque public IDs using the existing native child identity mapping. Discard sessionId, rollout path, previews, and extra fields. Cwd, origin and objective are sensitive authorized-consumer data, never diagnostics or evidence output.
3. Include all sourceKinds explicitly (the default list hides subagents), both nonarchived and archived pages, useStateDbOnly:true to avoid rollout repair. Cursor cycles, duplicate thread identities and malformed envelopes fail the collection; a row cap reports complete:false/scan_limit. Completeness describes this paged stored-thread read, not atomic or exhaustive fleet ancestry. Missing optional fields do not erase a valid thread. Parent null means ancestry_unavailable, never confirmed-root. Goal null means goal_absent for every goal field, not zero. A mismatched goal.threadId makes goal fields unavailable/identity_mismatch. Missing or invalid counters never coerce to zero. Expose status and running separately: active true, idle false; notLoaded/systemError cannot prove execution state. Model and effort are configured/persisted metadata, never per-turn route confirmation.
4. Goal updated and cleared notifications are validated and projected immediately on the same stream, with opaque thread identity and a connection-local sequence. A bounded async subscription buffers notifications during reads; overflow emits unavailable and closes rather than dropping changes silently. Validate nested goal.threadId matches notification.threadId. Each event carries native goal updatedAt as source time where present. No durable cursor or cross-process delivery is claimed. No polling or read-triggered mutation. Stop/EOF/error and unsubscribe are explicit; malformed relevant notifications fail visibly.
5. Synthetic tests cover projection, zero vs unknown, source errors, identity correlation, bounds, handshake order, all-source pagination, no forbidden RPCs, subscription updates/clear/overflow/disconnect. Mutation script breaks every new safety guard, demands a red assertion, restores exact bytes and demands a green positive control. Read-only live proof reports counts/presence/reasons only, never data. Live notification delivery may remain INCONCLUSIVE if no external producer emits; do not write a goal to manufacture the proof.
6. Publish one issue (no dispatch label), one draft PR against main, RFC using the existing numbered format, all command/exits/output evidence, independent non-OpenAI implementation review with fresh matrix before each attempt and 900-second cap. Leak scan before push.

Attribution: this is an additive native source, not a guessed issue assignment or replacement ancestry tree. Existing agent/cost contracts stay unchanged; goal budget/tokens/seconds are distinct native goal counters, not quota or currency. Consumers need to opt into this new read/stream surface. Missing native parents and absent goals remain visible gaps for the separately owned writer.

Owner forks: none; native-ID export is forbidden by the standing privacy constraint, so public thread references remain opaque. Scope and read-only behavior are explicit in the brief.

Risk gates: notification locality is unproven until a natural live event is received; no claim of global observation. Runtime metadata can be stale when not loaded, so it is labeled. Partial scans never become a complete issue tree. API/schema drift fails closed with a reason.

## Review clarifications

- The allowlist in item 1 is outbound only. Inbound goal updated/cleared notifications are separately allowlisted and decoded. Unknown notifications without IDs are ignored; unknown response IDs and unsolicited server requests with IDs fail closed. No mutation method is ever sent.
- Sensitive field policy: library read options default includeSensitive:false; cwd, git origin and goal objective then return unavailable/redacted, even if present. Explicit includeSensitive:true is reserved for an authenticated private consumer; CLI equivalent is --private. IDs always stay opaque in both modes. Public live evidence goes through a separate allowlist projection (counts, field availability and reasons only); tests inject canaries into every sensitive source field and assert their absence from default output/evidence. No API response, stderr, preview, path or sessionId is logged.
- IDs reuse the existing published native child identity formula in packages/telemetry/src/agent-observations.ts: agent_ + SHA256("agent" + NUL + "codex" + NUL + nativeThreadId). This is not encryption or authorization; native Codex UUIDv7 identity entropy and the existing namespace supply opacity. The task does not authorize replacing existing identities with a salted/random registry, which would break joins. Duplicate native IDs reject the collection. An identity replacement produces a different opaque identity; deleted records are not emitted; no continuity is inferred. No reverse lookup or native ID is exported. Cryptographic collision resistance is inherited, not a newly claimed guard.
