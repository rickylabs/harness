# Issue agent partial feed — locked plan

## Summary
Keep every safely bound issue in the snapshot when another receipt cannot bind, and inspect only Codex rollout date directories and creation timestamps in each receipt's bounded time window. Version the additive contract as 0.5.2. The coordinator's #387 runtime rerun is the external acceptance gate.

## Decisions
1. Add `complete` and typed `reason` to each `IssueAgentTree`. A complete issue has nonempty dispatches and null reason; an incomplete issue has empty dispatches and a non-null reason. The decoder accepts 0.5.1 issue rows lacking these fields as complete, preserving old frames. Top-level `complete` remains false if any issue is incomplete; its reason is a deterministic aggregate indicator.
2. Group validated dispatch records by repository and issue. Build and strict-decode each issue independently, then aggregate. A stale unmatched root yields its own incomplete issue row without removing a bound neighbour. A global unreadable source may still make the top-level frame incomplete, but safely bound issue rows remain available when their own evidence passes.
3. Read Orchid receipts before native sessions. For Codex, enumerate only UTC date directories intersecting each issue's receipt windows; accept only canonical rollout filenames whose creation timestamp falls in the window. The scan has a fixed 10-minute pre-dispatch margin and 24-hour post-dispatch ceiling, 20-file per-issue hard cap (even if the CLI limit is higher), and 8 MiB per-file and 32 MiB per-issue read caps. If capture time is later than dispatch time plus 24 hours, or a file/byte cap prevents proving ancestry, emit that issue with `scan_limit` unconditionally, not a false complete tree. Other telemetry backfill call sites keep their existing default scan.
4. Run one bounded scan per issue for Codex only, because the existing private Orchid native binding proves only Codex roots. Claude, agy and opencode issue rows get typed `binding_unavailable` without recursive native-store or database scans. Each scan's degraded flag applies only to that issue. At most eight recent dispatch windows (each 24 hours) are scanned per Codex issue; more dispatches make that issue `scan_limit`. Old receipts are emitted incomplete before I/O. A later bounded source adapter can add other transports.

## Forks, risks and gates
No owner fork is required to preserve truth: the 24-hour window is a conservative performance cap, and any run it cannot cover is marked `scan_limit`, not treated as complete. If the owner needs full older-running ancestry, extend the window under a measured I/O budget. Risk: a child created just outside the window; the ceiling and incomplete reason catch it. Risk: unrelated bad transcript affects a good issue; isolated scans and per-issue decoding catch this. Risk: private paths or IDs leak; only opaque IDs and fixed reasons cross the decoder. Gate: independent plan review before code; red mutation controls for cross-issue blanking and window selection; Node 24 build, contracts/telemetry suites, installed consumer, leak scan, independent implementation review, ready PR. Live #387 rerun is not claimed by local tests.
