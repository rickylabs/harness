## Independent implementation review (2026-09-27)

**Verdict: FAIL_FIX on the candidate diff reviewed here.** The per-issue grouping preserves #387 beside stale #378 in the synthetic integration test, and the new Codex path limits transcript reads. Four implementation details need correction before the ready PR; the Stage F/G plan verdict above remains PASS.

1. **Legacy partial frames are rejected.** The decoder treats every 0.5.1 issue row without `complete`/`reason` as complete (`packages/contracts/src/issue-agent-tree.ts:245-250`), then validates it as a complete native tree (`:285-293`). The previous producer could emit top-level `complete:false`, `reason:"ancestry_unavailable"` with a nonempty dispatch-only issue row when a root identity did not bind (`packages/telemetry/src/agent-observations.ts:55-70`; old `issue-agent-feed.ts` behavior at baseline 0751c76). That was valid in 0.5.1, so a 0.5.2 decoder must accept it. **Fix:** normalize such legacy issue rows to typed incomplete rows with empty dispatches, and test an actual old-style frame. A legacy complete row still normalizes to complete.
2. **Date-directory symlinks can redirect the scan.** `collectCodexWindows` follows `root/YYYY/MM/DD` through `stat`/`readdir` without checking directory components (`packages/telemetry/src/backfill/index.ts:153-177`). `readBounded` uses `O_NOFOLLOW` for the final file only (`:75-89`). The issue feed could read Codex-shaped JSONL outside the designated native store and project safe-looking labels into the public frame. **Fix:** reject symlinked root/date path components before enumerating, with a symlink-date test.
3. **Directory enumeration remains unbounded.** `readdir(dir, {withFileTypes:true})` materializes every entry in a date directory before the 20-file cap can apply (`packages/telemetry/src/backfill/index.ts:176-190`). This avoids the old whole-tree recursion but does not place a hard bound on directory metadata I/O or memory, a material concern for a 15-second feed on the measured HDD. **Fix:** use bounded streaming enumeration or an explicit entry-count ceiling that degrades the issue to `scan_limit`; test a directory above that ceiling. The 8 MiB/file, 32 MiB/frame and eight-window bounds should remain.

4. **Aggregate overflow can blank all bound neighbours again.** Each issue is decoded independently, but `combineIssueAgentTreeSnapshots` decodes the aggregate only after concatenation; if total agents or serialized bytes exceed the contract cap, it returns `issues:[]` (`packages/telemetry/src/issue-agent-feed.ts:160-164`; `packages/contracts/src/issue-agent-tree.ts:283,315`). **Fix:** apply a deterministic aggregate bound before final decoding, retaining safely bound issues within the cap and reporting global `scan_limit` for omissions. Test that an oversized neighbour does not erase an earlier good issue.

The scoped no-live-log architecture is recorded as drift and is consistent with Orchid's private Codex root binding (`packages/telemetry/src/orchid-native-binding.ts:29-55`). The coordinator's real-home #387 rerun remains an external acceptance gate.
