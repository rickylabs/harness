# Issue agent head scan — locked plan

## Summary
Classify bounded Codex `session_meta` heads before full transcript reads. Only the private Orchid root and its proven descendants consume the 8 MiB/file and 32 MiB/frame full-read budget. Search an offset-safe filename/date envelope around receipt time so native and reader timezone settings cannot silently exclude a child.

## Decisions
1. Keep the existing exact private binding. Add a private predicate that compares a `session_meta` id to the bound root without exporting the id or credential. The head reader mirrors the full Codex parser's identity grammar: `payload.id ?? session_id`, both direct `parent_thread_id` and `source.subagent.thread_spawn.parent_thread_id`, and rejection of conflicting/self parent claims. Select children only through that explicit parent chain. No path, cwd, prompt or model text becomes an identity join.
2. Expand each receipt window (ten minutes before dispatch through capture time, maximum 24 hours) by 24 hours on both sides for filename and day-directory selection. Treat filename wall-clock text as a sortable clock only; this envelope includes every civil UTC offset without trusting the runtime host timezone. Candidate enumeration remains capped at 1,000 directory entries per date and 128 canonical files per issue; exceeding either cap yields `scan_limit`. Read only the first `session_meta` line of each candidate with a 16 KiB cap and no-follow open. An invalid candidate head remains a typed incomplete source; a valid unrelated head is ignored even if its full file is huge.
3. Parse at most 20 selected root/descendant files with the existing full parser and 8 MiB/file, 32 MiB/frame cap. Require each full parse's id and parent to equal its selected head claim; a changed file is incomplete, never projected. Count head bytes toward the frame budget. A selected oversized file remains `scan_limit`; an unrelated oversized file cannot degrade the issue.
4. Add a synthetic real-shape fixture: two 20 MiB valid unrelated heads next to a small matching root+child, with UTC+2 filename clocks for a UTC receipt. Add a late child whose filename is shifted into the next date by a different plausible offset; it must still bind. Keep old generic backfill behaviour unchanged. Red mutation controls must catch removed head selection and removed offset envelope.
