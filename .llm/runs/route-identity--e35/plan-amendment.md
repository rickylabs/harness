These amendments supersede the named plan clauses without rewriting the reviewed plan. All 11 required findings from `adversarial-review.md` are accepted with the precise dispositions below. They do not authorize a live provider or transport.

1. **Request IDs (D-5):** the helper mints a fresh per-request id (for example Node `randomUUID`) and passes the whole request to the injected port. The port returns an unfiltered raw response; the helper independently compares its response id. No fixed global id, port-owned correlation, or request echo is accepted. Test concurrent cross-delivery and wrong ids. Source: `adversarial-review.md:9`.
2. **Exact observed keys (D-5):** observe only `result.modelProvider`, `result.model`, `result.reasoningEffort`, `result.cwd` and nonblank `result.thread.id` from the correctly correlated response. Request keys are `params.modelProvider`, `params.model`, `params.cwd`, `params.config.model_reasoning_effort`. Assert an input echo lacking response keys stays unknown. Source: `protocol-schema.md:13`.
3. **Vocabulary (D-2 / new IG-5):** caller supplies explicit server-vocabulary values; comparison never translates. Mapping matrix/provider identities and efforts into that vocabulary belongs to #53 composition and is unproven here. Exact equality is a conservative gate, not proof that every valid model alias is interoperable. Source: `adversarial-review.md:19`.
4. **Success (D-6):** return a `DispatchResult` carrying `verdict: accepted`, `run: {runId, provider: registrationId, external: verifiedThreadId}`, and mandatory known route evidence only after a correlated, structurally valid turn acknowledgement with a nonblank turn id. Registration id is separate from the requested modelProvider. Add a positive exact-result test and malformed/empty turn-id tests. No accepted return from this function may carry absent/non-known route evidence. Source: `adversarial-review.md:25`.
5. **Callable default (D-1):** export `isRouteVerified(result)` from subagents. It returns false for absent, unknown, or mismatch route evidence, even if a legacy/fabricated result says accepted. It returns true only for complete matching requested/observed values and a known status. Test both absent and contradictory accepted evidence. Legacy DispatchResult producers remain source-compatible; the new Codex function must never return accepted with non-known evidence. This protects the callable verification boundary without pretending TypeScript forbids a caller fabricating a result. Source: `adversarial-review.md:30`.
6. **Deterministic negatives:** complete nonblank case/alias/trailing-space/equivalent-looking cwd differences are mismatch. Missing/null/blank/wrong-type values are unknown. Relative requested cwd is invalid and must not become a known match; no filesystem canonicalization is performed. Pin each fixture's exact verdict. Source: `adversarial-review.md:36`.
7. **Mixed incomplete/different evidence:** unknown has precedence if any required field is invalid, but retain every known difference plus every invalid field in evidence and the diagnostic. Test provider mismatch plus null effort: unknown, zero turns, both facts visible. Source: `adversarial-review.md:41`.
8. **Retry guidance:** mismatch detail says to correct the requested route/server configuration before retry; unchanged settings may produce the same refusal. Do not assert that the server alone is necessarily wrong. `refused` still means no useful task was sent. Source: `packages/subagents/src/provider.ts:263`.
9. **Correlation source limits:** official documentation retrieved 2026-09-07 says: “Responses echo the id with either result or error”. Retained here as a short excerpt from https://learn.chatgpt.com/docs/app-server . A non-echoing server fails safely: absent/wrong id means unknown and no turn. The port is not trusted to certify correlation. Source: `protocol-schema.md:35`.

Fixtures use synthetic paths only. Source: `adversarial-review.md:60`.
