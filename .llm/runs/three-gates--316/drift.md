Baseline already includes earlier issue implementation. Preserve explicit missing-script configuration failures per owner clarification; add inconclusive for an audit that cannot inspect its subject. No architecture change.

2026-09-15 measurement: baseline `pnpm run typecheck` exited 126; its tsc shims reside on the same noexec mount as this checkout. Output said `tsc: Permission denied` yet the summary said compile ran. Extend the planned spawn-refusal guard to the shell's command-unavailable statuses 126/127. These are conventional shell statuses, not proof for arbitrary programs deliberately choosing those values; document this limit. Full successful gates will run on an owned executable checkout at `/tmp/harness-three-gates-316-verify` with the exact changed sources copied in, while the original checkout proves refusal handling.

A real missing-command control disproved the assumption that pnpm preserves shell 127. pnpm 11.25.0 maps it to exit 1 (`dist/pnpm.mjs:5702`), while its ndjson lifecycle record retains errno ENOENT. The stage runner now reads that structured error, forwards lifecycle/program output, omits package-manager debug metadata, and classifies the unavailable command as inconclusive. Output capture is bounded at 32 MiB; capture failure remains an inconclusive spawn/result error. This extends the same planned execution/refusal distinction without parsing diagnostic prose.

Final audit inspection found `existsSync` silently masks an inaccessible package manifest, allowing a mixed inventory to pass while omitting that package. Replace existence probing with a direct read, skipping only ENOENT (a non-package directory); all other filesystem errors remain INCONCLUSIVE. Added a deterministic EACCES control alongside valid/exempt packages and two mutations proving both inaccessible and genuinely absent manifest branches. This closes the planned inventory-unavailable boundary rather than changing workspace scope.
