# Implementation review — issue-agent-measured-running--p0

**Verdict: PASS after two bounded fixes.** D1, the frame-expiry gap, and D2, a contradictory terminal/running frame, are closed by the 0.5.3 decoder guard and tests. The telemetry producer's 105/120-second projection, native terminal precedence, and private identity boundary are sound for this scoped change. Live-home running proof remains unproven under plan spike S1 because the dispatcher has not yet supplied an early native binding.

## Finding 1 — a running frame can outlive its measured leaf

`measuredRunning` accepts only a `running` native outcome with a canonical event timestamp at or before capture and with event time + 120 seconds at least capture + the shared frame freshness interval (`packages/telemetry/src/agent-observations.ts:15-28`). The tree producer copies this value into `liveness` and gives the snapshot a 15-second deadline (`packages/telemetry/src/issue-agent-feed.ts:58-62,125-130`). This producer path meets the plan's timing rule (`plan.md`, Decisions 1 and 3).

The public decoder accepts a running `liveness` row by shape and timestamp at capture (`packages/contracts/src/issue-agent-tree.ts:185-191`). Its nested observation decoder requires an available leaf's `validUntil` to be valid only at capture (`packages/contracts/src/agent-observations.ts:137-150`). It validates the frame's own 15-second deadline separately (`packages/contracts/src/issue-agent-tree.ts:231-238`) and never checks that the running leaf remains valid through that deadline (`packages/contracts/src/issue-agent-tree.ts:288-320`). A consumer that trusts the decoded snapshot can therefore display `running` after the cited measurement has expired.

Read-only reproduction against the built modules: construct a valid bound running frame, then change only `observation.running.validUntil` to one second after capture. `readIssueAgentTreeSnapshot` returned `ok: true` both before and after the change. The changed frame expired at `2026-01-01T00:01:46.000Z`; its running leaf expired at `2026-01-01T00:01:32.000Z`. The probe exited 0 and printed `{"originalOk":true,"state":"running","frameValidUntil":"2026-01-01T00:01:46.000Z","leafValidUntil":"2026-01-01T00:01:32.000Z","mutatedOk":true}`.

**Required fix, completed:** In the public tree decoder, require a `running` row's nested `observation.running.value` to be `true`, its observation time to match `liveness.observedAt`, and its `validUntil` to cover the snapshot's `validUntil`. Keep older unknown and ended frames readable.

**Re-review disposition: closed.** The decoder now checks value, matching observation time, and a deadline covering the frame (`packages/contracts/src/issue-agent-tree.ts:299-304`). The contract test accepts exact equality and rejects early/null deadlines, false/missing values, and a mismatched time while keeping unknown and ended rows readable (`packages/contracts/src/issue-agent-tree.test.ts:35-54`). A read-only repeat of the original probe returned `{"originalOk":true,"expiredLeafOk":false,"expiredLeafReason":"invalid"}`. The author reports Node 24 contract and telemetry suites passed and separate deadline/time guard removals made the focused test red before restoration. The 0.5.3 package version and decoder note are present (`packages/contracts/package.json:3`; `packages/contracts/README.md`, per-issue agent trees section).

## Finding 2 — terminal and running can both be true in one decoded row

The telemetry producer marks a terminal native outcome as `ended` before considering a running observation (`packages/telemetry/src/issue-agent-feed.ts:58-69`), and `measuredRunning` emits no true leaf for a terminal run (`packages/telemetry/src/agent-observations.ts:18-26`). The public decoder validates terminal outcome shape and permits it when liveness is ended (`packages/contracts/src/issue-agent-tree.ts:185-201`), but its new cross-check runs only when liveness is `running` (`packages/contracts/src/issue-agent-tree.ts:299-304`). It therefore accepts `liveness.state=ended`, a sourced `terminalOutcome=succeeded`, and `observation.running.value=true` in the same row. Different consumers could render conflicting current states from one accepted frame.

Read-only reproduction against the rebuilt modules: start with a valid produced running frame, change its `liveness` to `ended/native-outcome` and `terminalOutcome` to `succeeded/native-outcome`, and leave its nested running leaf true. `readIssueAgentTreeSnapshot` returned `{"contradictoryOk":true,"liveness":"ended","runningLeaf":true}`. This is a decoder consistency gap; the current producer did not generate the contradictory row.

**Re-review disposition: closed.** The decoder now rejects a true running leaf unless liveness itself is `running` (`packages/contracts/src/issue-agent-tree.ts:299-304`). The contract test rejects both `unknown` and `ended` liveness paired with a true leaf, while accepting legacy unknown and ended rows with unavailable running (`packages/contracts/src/issue-agent-tree.test.ts:51-57`). A read-only repeat of the contradictory-frame probe returned `{"validRunning":true,"endedWithRunning":false}`. The author reports a deliberate removal of this guard made the focused contract test fail, followed by a restored passing build and test.

## Other checks

- **Source and terminal precedence:** Codex's parser sets `running` on `task_started`, clears it on complete/error/abort, and can resume on a later `task_started` (`packages/telemetry/src/backfill/codex.ts:232-235`). The projection applies `measuredRunning` only after exact dispatcher/native root binding and same-source parent traversal (`packages/telemetry/src/agent-observations.ts:59-120`). The tree's terminal branch wins over a running leaf (`packages/telemetry/src/issue-agent-feed.ts:58-69`). The multi-turn parser and tree tests cover this order (`packages/telemetry/src/backfill/codex.test.ts:159-164`; `packages/telemetry/src/issue-agent-feed.test.ts:65-81`).
- **Privacy and other callers:** The new running revision hashes source, private run ID, and event time; the public value contains the hash and timestamp, not the ID or origin path (`packages/telemetry/src/agent-observations.ts:25-27`). The canary tree test asserts those private strings are absent (`packages/telemetry/src/issue-agent-feed.test.ts:33-50`). The shared observation builder also feeds `runs --json` (`packages/telemetry/src/cli.ts:604-614`), so that caller receives the same bounded running leaf. Claude and opencode backfill currently emit `unknown` outcomes (`packages/telemetry/src/backfill/claude.ts:271`; `packages/telemetry/src/backfill/opencode.ts:150`), so this change does not newly claim they are running.
- **Proof limit:** Synthetic tests and the read-only decoder probe do not establish live-home running. The plan and Stage G evaluation explicitly leave S1 unproven (`plan.md`, Owner forks and spikes; `plan-eval.md`).

The NetScript implementation evaluator transport exception is recorded in `drift.md`; this review makes no claim of route parity.
