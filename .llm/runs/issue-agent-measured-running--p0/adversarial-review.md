# Stage F adversarial review — issue-agent-measured-running--p0

**Verdict: PASS.** The amended plan derives running from a bounded native task state, preserves terminal precedence, and fences each running observation through the full 15-second public frame lifetime. Live-home acceptance remains an explicit integration gate.

## Findings and dispositions

1. **F1 — Goal `active` is not runtime running. Closed by amendment.** The first plan treated an exact `thread/goal/get` result with status `active` as running. The [Codex goals guide](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex) says an active goal can persist while its thread is idle; the local projector separately derives thread running from thread status (`packages/telemetry/src/codex-thread-project.ts:23-50`). The public tree calls running evidence `runtime-observation` (`packages/contracts/src/issue-agent-tree.ts:26-29`). Amended Decision 1 uses a dispatcher-bound native `RunRecord.outcome === running` and recent event time; Decision 3 removes app-server queries from this feed. `drift.md` records the change.
2. **F2 — Post-scan goal measurement would conflict with snapshot time. Closed by amendment.** The CLI captures snapshot time before its async disk collection (`packages/telemetry/src/issue-agent-feed-cli.ts:131-142`), and an available observation may not have a future `observedAt` (`packages/contracts/src/agent-observations.ts:137-150`). Removing post-scan goal reads removes the backdating problem. The native event timestamp is checked against capture; a newly appended event after capture is conservatively unavailable until the next frame. Test future-time rejection.
3. **F3 — A per-request timeout would not bound the frame. Closed by amendment.** The first plan could perform sequential initialize and goal requests under a 15-second tree freshness contract (`packages/telemetry/src/codex-thread-connection.ts:24-44`; `packages/contracts/src/issue-agent-tree.ts:7,85-86`). The revised plan adds no RPC and stays within the existing bounded disk scan (`packages/telemetry/src/issue-agent-feed-cli.ts:22-25,47-63`). The CLI's post-collection expiry check remains the frame deadline (`packages/telemetry/src/issue-agent-feed-cli.ts:141-142`).
4. **F4 — A leaf valid only at capture could outlive its own evidence while the frame remains valid. Closed by amendment.** The reader checks an available leaf against capture, while the tree remains valid for 15 seconds (`packages/contracts/src/agent-observations.ts:137-144`; `packages/contracts/src/issue-agent-tree.ts:7,237-238`). Amended Decision 1 requires event age at most 105 seconds at capture and `running.validUntil = event + 120 seconds` to cover `snapshot.validUntil`. This gives the stated two-minute upper bound on stale display and covers the coordinator's 90-second hold. Test both sides of the 105-second cutoff and frame expiry.
5. **F5 — Native recency is a bounded inference. Accepted, with explicit limit.** The parser derives outcome from ordered `task_started` and terminal events, while `updatedAt` is the last known event timestamp (`packages/telemetry/src/backfill/codex.ts:169-173,232-235,243-257`). An abrupt process exit without a terminal event can leave running visible until the two-minute deadline. The plan states this cost and requires future-time, expiry, terminal, ancestry, and multi-turn tests. No exact end time is inferred.
