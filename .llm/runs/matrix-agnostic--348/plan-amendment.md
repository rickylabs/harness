# Matrix agnostic — plan amendment

Resolve the independent plan-review findings before implementation. This amends the locked plan without rewriting it.

1. Router IDs are nonempty, at most 4096 characters and match `^[a-z0-9][a-z0-9_.-]*$`. Paired tests reject space, slash, uppercase and shell metacharacters. The wire retains its existing encoding guards; the routing document owns registration.
2. `FallbackTrigger` becomes string. The resolver matches triggers only against the already validated chain's `when` values; undeclared inputs return no-route. Repo search found no coordinator/dsh-app caller of resolveFallback and no separate trigger validator: this is the existing public integration boundary. A custom-trigger resolution/admission test is the end-to-end package gate; there is no invented coordinator wiring.
3. All document-internal lane references remain canonical. Aliases apply only to caller queries (lanePolicy, laneChain, admission, laneConstraint and tierRoleLane). Refuse alias targets that are aliases and alias keys that collide with canonical lanes. Catalog preserves the alias map separately. No diagnostic index can be computed from a noncanonical document reference.
4. Coverage is a declared certifying seat, including triggered or paid fallbacks; it is not availability or launch permission. Preserve the existing fallback-based matrix rather than silently redesign its route choices. The runtime still requires the declared trigger, turn boundary, depth and explicit paid approval. Test that a covered paid fallback remains unlaunchable without approval; this is deliberately distinct from document validity. A generic any seat can serve other families and is legal; reject a tier with only same-family any coverage and skip that seat when resolving for that author. Globally rejecting any for matching its own model family would reject every any seat even when no author from that family is bound.
5. A plan without plan_evaluation is accepted; a plan_evaluation without plan is refused. An implementation-purpose lane must be the implementation binding of a tier regardless of other role uses. If both review and implementation_evaluation exist, tierPlan.review preserves the explicit legacy review binding; both coverage pairs are checked. All new fixed field names enter STRUCTURAL_FIELDS; arbitrary role names stay indexed.

No owner fork: these choices preserve current launch/budget behavior and baseline route selections while enforcing the brief's explicit opposite-family coverage rule. Live availability remains INCONCLUSIVE without probes.
