# Matrix agnostic — locked plan

Make routing owner-maintained JSON while keeping unsafe documents refusable. Authorized by the matrix-agnostic brief; no owner preference fork remains.

1. Add optional document `triggers`, `routers`, `laneAliases`, model `label`/`description`. Legacy v1 omissions retain their existing trigger/router vocabulary; explicit lists fully replace it. Purposes already open. Keep schema v1 as a backward-compatible extension, not a competing fleet v2 design.
2. Tier rows become open role-to-lane maps. Accept canonical `implementation` / `implementation_evaluation`, optional `plan` / `plan_evaluation` and arbitrary other roles. Preserve `implement` / `review` callers through queries and aliases. Validate every reference; implementation and review bindings are required (legacy spellings accepted). If both implementation spellings occur, they must agree. A separate legacy review lane may coexist with a formal implementation evaluator; both must cover every author step. Validate plan coverage whenever a plan evaluator is bound. Expose `tierRoleLane` and `resolveTierRole` so callers never infer names.
3. Rename harness-bearing lanes in the shipped document to tier/role names with explicit one-hop aliases. Bind tier-local formal evaluators directly. Add a chore tier for the existing orphan implementation lane; use its existing generic opposite-family evaluator. No model choices change.
4. Coverage requires a registered, opposite-family, certifying reviewer for each implementation step, including fallback steps and implementation lanes absent from tiers (reject unbound implementation lanes). `any` never overrides family independence. Resolution with an author family skips same-family certifiers, including fallbacks. Keep evaluation/implementation purposes as semantic safety markers; arbitrary other purposes remain legal.
5. Export a JSON-serializable editor catalog from routing: supported harnesses/transports, configured routers/efforts/triggers/purposes/families/lanes/tier roles, registered model ID/label/description/family plus route choices and search text. Mark configured routes as unproven availability. No network or UI added. Enforce labels as nonempty bounded strings.
6. Router strings survive the subagents wire round-trip. Known router list becomes legacy suggestions, not an allowlist. Retain encoding safety and executor harness vocabulary.
7. Isolate existing model-specific tests on a compact frozen fixture, never the live config. Add a small synthetic matrix for custom models/routers/triggers/roles and paired negative controls. Live tests assert invariants only. Mutation verification breaks each new guard, observes refusal, restores and observes acceptance; also substitute renamed models/routers/efforts in live data to prove no test owns policy. All commands bounded.

Dependency DAG: research → independent plan review → schema/queries → resolution/catalog → config/fixtures → mutation controls → full routing/coordinator/telemetry suites → independent implementation review → commit/push/update PR.

Risks: alias ambiguity (reject collisions, dangling targets and alias chains); evaluator coverage bypass (paired mutation cases, including any and orphan lanes); schema/catalog divergence (derive choices from validated document); router serialization loss (round-trip test); weekly model churn (live substitution test); catalog misread as availability (explicit unproven marker). Harness and transport mechanics, certification keywords, subscription payment semantics, bounded plain-data validation, credential/encoding guards and ordered-effort escalation remain closed for actual execution and safety reasons.

Spikes/integration gates: live cockpit rendering and provider reachability INCONCLUSIVE here; catalog is the integration boundary. Independent plan/implementation evaluation is required. Tests are not independent certification.
