Governing consumer amendment v3 — 2026-09-08
This amendment overrides plan-v2 where specified; remaining rules survive. Public-facing findings are anonymized. This is a changed plan candidate, not covered by round2 PASS until reviewed.

C1 identity/issuer. Enrollment authority (backend or operator) allocates opaque namespace, bindingId, bindingRevision, sourceScopeId. Namespace distinguishes enrollment authorities; sourceScopeId distinguishes native stores within that namespace. No value is derived from a path or transcript prose. Root binding now exact {namespace,id,revision,sourceScopeId,repo:{owner,name}}; all new IDs use existing bounded identifier syntax. Native identity is the TUPLE(namespace,sourceScopeId,run.source,run.nativeId), never bare nativeId; the observation belongs to (namespace,binding.id,binding.revision). Two native stores with identical run IDs remain distinct. Binding id stable for enrolled association; sourceScopeId stable for enrolled store and must never be reused for a different store. No global uniqueness claim beyond issuer obligation. Backend must enforce uniqueness on enrollment; producer cannot detect duplicate configuration in other instances. Equality only, case-sensitive, no lexical/numeric ordering.

C2 revision semantics. Issuer must allocate a never-reused revision whenever RepoRef, selected native run, sourceScopeId, source root/selected file path, worktree, expected Git common-directory association, or binding scope changes. File append/content growth in same enrolled source does not itself change binding revision, though it can make an in-flight read incomplete. Rebinding to a different store requires a new sourceScopeId. File replacement at same path detected in-read is unusable; subsequent read under unchanged descriptor can identify the same logical native run only if all identity/scope checks pass, never claim inode continuity. Receiver must keep enrollment revision current and atomically compare namespace/id/revision plus sourceScopeId before persistence and protected delivery. Producer supplies exactly its snapshot identity and never checks remote principal state. A delayed A result cannot be relabeled as B. Old scoped observations may be retained only under their original binding and explicit backend policy; never silently reassigned.

C3 assertion versus verification. Descriptor's logical RepoRef->worktree association is asserted by trusted enrollment; matching Git identity and native cwd are locally checked facts, not durable historical membership or cryptographic source provenance. Add root verification:null|{basis:enrollment-and-local-worktree,verifiedAt}. Nonnull exactly when coverage read (run nonnull); otherwise null. verifiedAt is local end-of-validation time after final consistency checks, capturedAt local collection completion thereafter; both canonical dates with verifiedAt<=capturedAt. Neither refreshes native evidence. No invented verification time for an unavailable read. This is conservative: even a source outage with valid initial binding yields verification:null for the new observation, not invalidation of an older verified read by itself.

C4 consistency algorithm. Snapshot descriptor bytes and opened identity before first verification. Snapshot canonical source-root/worktree/common-directory identity(dev,ino) and relevant Git identity result. Collect bounded source file using v2 before/after opened and path identities. Before serialization re-read descriptor (same size bounds) and compare bytes plus opened/path identity; recanonicalize source root, selected source file, worktree, expected common directory and repeat Git identity checks. Use fixed argv and sanitized Git environment that clears path-redirecting GIT_* variables; no inherited GIT_DIR/GIT_WORK_TREE override. On descriptor change/replacement emit coverage incomplete/binding-changed with the ORIGINAL valid snapshot binding, run:null, verification:null. On source-root/worktree/common-directory/Git association identity change, same binding-changed. Source file growth/replacement alone remains incomplete/source-changed. If final read/check cannot establish consistency, binding-changed or source-changed according to affected object, never a successful payload. Add binding-changed to incomplete reason union; unknown future reason rejected by decoder.
This detects observed before/after changes, not an atomic filesystem snapshot or adversarial ABA proof. Trusted enrolled local storage assumption remains explicit. A change after final checks is a later observation; backend current-binding fencing still necessary. Deterministic test seams pause read at named checkpoints without sleeping. Descriptor reversion/hostile filesystem immunity not claimed.

C5 classifications/retention. Source missing/unreadable/too-large distinguished from scope-unverified/scope-mismatch/identity errors and binding-changed using typed reason, never notes. Invalid descriptor remains exit1 fixed diagnostic/no document. Principal denial/expiry NEVER emitted by this producer; backend-owned denial signal and grant checks before protected delivery. A new unavailable/unverified read cannot update prior source evidence, extend authorization or establish new binding ownership. Prior authorized evidence may remain stale under same binding per backend policy, with original times; revocation/expiry overrides retention. No instant offline revocation guarantee or client cache policy is authored here.

C6 evidence/partial tail. v2 withholds whole run for malformed tail because its contents can hide identity/scope change. No new partial payload. Retaining prior successfully verified observation during loss is distinct and backend-owned. first/lastObservedAt are validated envelope evidence times, not original launch/end guarantees. Token units are source-reported token COUNTS (nonnegative safe integers, cumulative native totals, no summing); missing fields unknown. Cost/quota unsupported. This is one selected run, neither complete repo census, decision evidence, all-clear nor liveness certification.

Actual backend must test atomic fence and protected delivery. Verification clock separate from original evidence and absent on unread arms. Provider/schema collision and cross-binding replay negative tests.
